# ООО «ФЕДСТРОЙ» — Корпоративный сайт

Сайт строительной компании ООО «ФЕДСТРОЙ» (проектирование, производство подсистем, монтаж навесных вентилируемых фасадов и фальшполов).

## Стек технологий

- **Разметка:** HTML5 (модульная компоновка из `blocks/`)
- **Стили:** Tailwind CSS v4 (локальная CLI-компиляция), кастомные стили (`css/style.css`, `css/adaptive.css`)
- **Скрипты:** Vanilla JavaScript (ES-модули `js/modules/`, fallback `app.js`)
- **Бэкенд:** Node.js, Express, Multer, dotenv, node-fetch
- **Интеграции:** Telegram Bot API (уведомления и передача файлов ТЗ)

## Установка и запуск

### 1. Установка зависимостей

```bash
npm install
```

### 2. Сборка статических файлов

```bash
# Разовая компиляция CSS, HTML и JS-бандла
npm run build

# Режим отслеживания изменений (blocks/, css/, js/, src/)
npm run watch
```

### 3. Настройка окружения (бэкенд)

Для отправки уведомлений в Telegram скопируйте `.env.example` в `.env` и укажите данные бота:

```bash
cp .env.example .env
```

Параметры `.env`:
- `PORT` — порт сервера (по умолчанию `8080`)
- `TELEGRAM_BOT_TOKEN` — токен бота Telegram (получить у `@BotFather`)
- `TELEGRAM_CHAT_ID` — ID чата или группы для получения заявок

### 4. Запуск сервера

```bash
npm start
```

Сервер запускается на `http://localhost:8080` и обрабатывает:
- Раздачу статики (`index.html`, стили, скрипты, юридические страницы)
- API эндпоинты

## API

### `POST /api/lead`
Принимает заявки с сайта (`multipart/form-data`).

**Параметры запроса:**
- `name` *(string)* — имя контактного лица
- `phone` *(string, обязательный)* — контактный номер телефона (РФ, 10–11 цифр)
- `service` *(string)* — наименование выбранной услуги
- `area` *(string)* — площадь объекта (м²)
- `building` *(string)* — тип здания
- `comment` *(string)* — комментарий / примечание
- `source` *(string)* — источник заявки (форма, калькулятор, квиз, модалка)
- `attachment` *(file, опционально)* — файл ТЗ или чертеж (.dwg, .pdf, .zip и др. до 35 МБ); только одно вложение

**Ответ (успех, HTTP 200):**
```json
{
  "success": true,
  "leadId": "ФС-20260923-a4f2e1c8",
  "message": "Заявка зарегистрирована. Инженер ПТО получит уведомление."
}
```

**Ответ (ошибка валидации, HTTP 400):**
```json
{
  "success": false,
  "error": "Пожалуйста, укажите корректный контактный номер телефона РФ (10–11 цифр)."
}
```

### `GET /api/health`
Проверка состояния сервиса. Возвращает статус, имя сервиса и аптайм.

## Тестирование

```bash
npm test
```

Запускает два последовательных набора:

**`test/test-scenarios.js` — API/integration (10 тестов)**
Поднимает реальный Express-сервер на тестовом порту и гоняет HTTP-запросы:
- Граничные условия размера файла: 1 байт, 100 КБ, ровно 35 МБ (допустимо), 35 МБ+1 байт (400), 100 МБ (400)
- Подмена расширений: MZ-сигнатура под `.dwg`, мусор под `.pdf`
- Параллельная отправка: уникальность `leadId` и имён файлов
- Персистентность: данные сохраняются после перезапуска сервера
- Пустой файл 0 байт → 400

**`test/dom-e2e.js` — JSDOM E2E (11 тестов)**
Загружает `index.html` в JSDOM и тестирует DOM-логику + HTTP через реальный сервер:
- Инициализация DOM, секции
- Мобильное меню
- Квиз (шаги 1→5, черновик ПР-XXXX)
- Клиентская валидация форм
- Сквозная отправка → экран успеха с ФС-номером
- Поведение при ошибках API: HTTP 500, 502, `success:false`, невалидный JSON, `success:true` без `leadId`
- FormData bridge с Blob-вложением

**`test/browser.pw.js` — Browser E2E на Playwright / Chromium (7 тестов)**
Запуск:
```bash
npm run test:e2e
```
Проверяет реальный браузер в двух режимах (`chromium-desktop` 1280×800 и `chromium-mobile` Pixel 5):
- Реальный выбор файла `.dwg` через `<input type="file">` и отображение превью через `uploader.js`
- Сквозная отправка формы с чертежом на сервер → генерация `ФС-YYYYMMDD-xxxxxxxx`
- Клиентская валидация в живом UI (ошибки незаполненных полей)
- Навигация по якорным ссылкам в шапке
- Полное прохождение интерактивного квиза (шаги 1→5, расчет сметы)
- Мобильный адаптив: отсутствие горизонтального скролла (`scrollWidth <= clientWidth`), доступность кнопки отправки без обрезания
- Мобильное бургер-меню (открытие/закрытие)
- Отправка заявки со смартфона

### Безопасность файлов

Сервер выполняет сигнатурную проверку содержимого для части поддерживаемых форматов:
- **Исполняемые файлы:** PE (MZ), ELF (`\x7fELF`), shebang (`#!`) — отклоняются для любого расширения
- **PDF:** проверяется заголовок `%PDF`
- **PNG:** проверяются байты `\x89PNG`
- **JPG/JPEG:** проверяются байты `\xFF\xD8\xFF`

Для архивных форматов (ZIP, RAR, 7z) и DWG сигнатурная проверка содержимого не выполняется —
работает только whitelist по расширению как первый рубеж через Multer `fileFilter`.
